My Journey from Problem Solving to Building Real Applications

📅 February 3, 2026 ⏱️ 5 min read 🏷️ Tech & Career

When I first started my Computer Science journey, I thought solving LeetCode problems and winning coding contests was the ultimate goal. But as I progressed through my third year at university, I realized that building real-world applications taught me lessons that no competitive programming problem ever could.

The Competitive Programming Phase

Like many CSE students in Bangladesh, I started with competitive programming. The thrill of solving a difficult algorithm problem, the satisfaction of seeing "Accepted" after hours of debugging – it was addictive. I spent countless nights on Codeforces, solving problems, learning data structures, and understanding algorithmic complexity.

This phase taught me:

  • Logical thinking: Breaking down complex problems into smaller, manageable parts
  • Efficiency mindset: Always thinking about time and space complexity
  • Persistence: Not giving up when a solution doesn't work the first time
  • Pattern recognition: Identifying similar problems and applying known solutions

The Transition to Real Applications

Everything changed when I built my first real project – a Coffee Shop Inventory Management System. Suddenly, I wasn't just writing algorithms; I was thinking about user experience, database design, error handling, and deployment.

I realized that:

  • Users don't care about your O(n log n) solution if the UI is confusing
  • A working solution deployed is better than a perfect solution in your IDE
  • Real applications need proper error handling, logging, and maintenance
  • Code readability matters more than cleverness when working in teams

Building My Portfolio Projects

With this new mindset, I started building practical applications:

Weather Application: This taught me how to work with external APIs, handle asynchronous operations, and store user data in Oracle Database. It wasn't about the most efficient algorithm – it was about creating a smooth user experience.

Language Translator App: Here, I learned Python API integration and how to handle real-time translation. The focus was on reliability and user-friendly design.

World Happiness Analysis Project: This project combined my data structure knowledge with practical data visualization. I learned that presenting data clearly is as important as processing it efficiently.

The Best of Both Worlds

Today, I'm grateful for both experiences. Competitive programming gave me a strong foundation in algorithms and problem-solving. Building real applications taught me software engineering, user empathy, and the importance of shipping products.

My advice to fellow CSE students in Bangladesh:

  • Don't choose between competitive programming and development – do both!
  • Start building projects early, even if they're simple
  • Focus on solving real problems that people around you face
  • Learn to deploy and maintain your applications
  • Don't be afraid to show your work, even if it's not perfect

Looking Forward

As I continue my journey, I'm excited to bridge the gap between algorithmic thinking and practical development. Whether it's optimizing database queries, building scalable web applications, or creating user-friendly interfaces, every day brings new learning opportunities.

Remember: The goal isn't to be the best at competitive programming OR the best at development. The goal is to be a well-rounded engineer who can think algorithmically AND build products that people love to use.

What's your journey been like? Are you more into competitive programming or building applications? I'd love to hear your thoughts!
